```
└─ integrations/supabase/*           ← GENERATED by Lovable after G3. Never edit.
```

**Why folders matter here.** Lovable's Vite wrapper (`@lovable.dev/vite-tanstack-config` 2.25.3) replaces TanStack's
default import protection with one rule: files under a folder named `server/` (and modules that import
`@tanstack/react-start/server-only`) may not be imported by browser code. A file merely **named** `*.server.ts`
outside `src/server/` is **not** protected and will leak into the browser bundle (confirmed in a test build).
So: server-only code lives in `src/server/` **and** starts with the marker line. The project's ESLint hint
("Rename the module to `*.server.ts`") is misleading under this config; ignore it.

| File kind | May import | Must never import |
|---|---|---|
| `src/server/*.server.ts` | anything, incl. other `src/server/*`, `@/lib/backend/*` pure helpers and schemas | React, components, `*.functions.ts` |
| `src/lib/backend/*.functions.ts` | `@/server/*` (top-level static import is fine: it is stripped from the browser build together with the handler; verified by the leak grep), schemas, helpers, `auth.middleware.ts` | `@/integrations/supabase/client.server` (go through `@/server/supabase-admin.server`) |
| `src/lib/backend/*.schema.ts`, pure helpers | `zod`, other pure helpers, `@/content/site` types | anything in `@/server/*`, `@/integrations/supabase/*` |
| Components, routes, hooks | `*.functions.ts` (via `useServerFn`), schemas, helpers, `@/integrations/supabase/client` (**auth only**, admin pages) | anything in `@/server/*`, `client.server` |

Rules:
- **`*.functions.ts` export nothing but `createServerFn(...)` results** (R-26). Types, schemas, constants and helpers go
  in `<area>.schema.ts`, a pure helper, or `src/server/*`. Imports from `@/server/*` are used **only inside
  `.handler()` bodies** (top-level `import` lines are fine: the compiler strips them with the handler, and the leak grep
  proves it). Never call an `@/server/*` function at module top level or from a `.validator()`.
- First line of every `src/server/*.server.ts`: `import "@tanstack/react-start/server-only";`
- Never create `src/server/index.ts` (the SSR entry is the file `src/server.ts`; don't touch it).
- Never put `*.functions.ts`, hooks or components inside a folder named `server`.
- F0-03 adds an ESLint `no-restricted-imports` path for `@/integrations/supabase/client.server` with the message
  "Import supabaseAdmin from @/server/supabase-admin.server" and turns it off for `src/server/**`.

## 2. The three Supabase clients

All three come from files Lovable generates when Cloud is enabled (G3). Shapes below were read from the user's own
Cloud-enabled TanStack Start project.

| Client | Import | Runs | Key | RLS | Use for |
|---|---|---|---|---|---|
| Browser client `supabase` | `@/integrations/supabase/client` | browser | publishable | yes (as the signed-in user) | **Admin auth only**: `signInWithPassword`, `signOut`, `getSession`, `onAuthStateChange`. Never `.from()` or `.rpc()` from the browser (D3). |
| Staff client `context.supabase` | provided by the generated `requireSupabaseAuth` middleware (wrapped by our `requireStaff`) | server | publishable + the staff user's Bearer token | **yes**, as that staff user (`auth.uid()` = staff id, so audit triggers record the right actor) | Every staff and owner server function (D4). |
| Service-role client `supabaseAdmin` | `@/server/supabase-admin.server` **only** | server | service role | **bypassed** | Public functions (`/book`, `getOpenSessions`), private-link functions (`/enrol`, `/my`), `notifyStaff`, `checkRateLimit`, and `auth.admin.*` in owner staff-role functions. Every query **must** filter by the request or family it resolved. |

How the staff token travels: Lovable registers `attachSupabaseAuth` as a global `functionMiddleware` in
`src/start.ts`; it adds `Authorization: Bearer <access_token>` from the browser session to every server-function call.
`requireSupabaseAuth` verifies it with `supabase.auth.getClaims(token)` and **throws plain `Error("Unauthorized: …")`**
when the header is missing or invalid. The admin UI treats any message starting with `Unauthorized` as "signed out"
(§ 11). Because the session lives in `localStorage`, SSR can't see the user: all `/admin` routes are `ssr: false`.

✅ `src/server/supabase-admin.server.ts` (F0-07):

```ts
import "@tanstack/react-start/server-only";

/**
 * The ONLY door to the service-role client (bypasses RLS). The generated file has no server-only
 * marker and is not in a server/ folder, so import it through here and nowhere else (D4, F0-07).
 */
export { supabaseAdmin } from "@/integrations/supabase/client.server";
```

Row types: after G4, use the generated types instead of hand-written ones, e.g.
`import type { Database } from "@/integrations/supabase/types";`
`type BookingRequestRow = Database["public"]["Tables"]["booking_requests"]["Row"];`
(Lovable's generated file usually also exports helpers such as `Tables<"booking_requests">`; check the file after G4
before relying on them.) Server functions return **camelCase view types** declared in `<area>.schema.ts`, never raw rows,
so the browser never receives columns it doesn't need (e.g. `retain_until`, `token_hash`).

## 3. Environment variables on Cloudflare Workers

Lovable hosting runs the server on Cloudflare Workers (`nodejs_compat`). Runtime secrets arrive in `process.env`.
`import.meta.env` contains only `VITE_*` values baked in at build time: **never** read a secret from it.

✅ `src/server/env.server.ts` (F0-01):

```ts
import "@tanstack/react-start/server-only";

/**
 * Runtime secrets on Lovable hosting (Cloudflare Workers, nodejs_compat) arrive in process.env.
 * Call these INSIDE handlers, never at module top level. Bracket form is required by tsconfig.
 */
export function requireServerEnv(name: string): string {
  const value = process.env[name];
  if (!value) throw new Error(`missing_env:${name}`); // name only, never the value
  return value;
}

export function optionalServerEnv(name: string): string | undefined {
  const value = process.env[name];
  return value ? value : undefined;
}
```

Rules:
- Call `requireServerEnv` / `optionalServerEnv` **inside** handlers or inside functions called by handlers, never at
  module top level (the Worker may not have the value yet when the module loads).
- Bracket form `process.env["NAME"]` only (`noPropertyAccessFromIndexSignature`).
- Error messages contain the variable **name**, never its value.
- Optional integrations (LINE alerts, Turnstile) use `optionalServerEnv` and degrade gracefully (alert `failed` with
  `missing_config`; Turnstile fails closed with the LINE fallback). `IP_HASH_SECRET` uses `requireServerEnv` (no
  silent fallback to an unsalted hash).
- `PUBLIC_SITE_URL` (no trailing slash) builds links in alerts and private links; when unset (local development and preview only; the live site must set it), use `getRequestUrl().origin` from `@tanstack/react-start/server`.
  **Value for this studio: `https://cherryleeandco.com`** (owner decision 9, 14 Oct 2026; the domain is live, G13 done).
  It is not a secret: set it as a plain variable at G6. Every absolute link in this file (staff alerts, `/enrol` and
  `/my` links) is built from it.

Names (values are set by the owner at G6; never in chat, code, tests or commits): `IP_HASH_SECRET`,
`TURNSTILE_SECRET_KEY`, `LINE_ALERT_CHANNEL_ID`, `LINE_ALERT_CHANNEL_SECRET`, `LINE_ALERT_TO`, `PUBLIC_SITE_URL`;
optional `PROMPTPAY_ID`, `RESEND_API_KEY`, `STAFF_NOTIFY_EMAIL`. Lovable-managed: `SUPABASE_URL`,
`SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SERVICE_ROLE_KEY` (read only by the generated files).
Public constants (Turnstile site key, Umami id) live in `src/lib/backend/public-config.ts` (§ 8), not in `.env`.

## 4. Shared result type, error codes and their TH/EN messages

✅ (rev) `src/lib/backend/result.ts` (F0-02, card P0-02; adds `family_restricted`, D28):

```ts
/** Result shape for PUBLIC server functions (no login). They never throw for expected problems. */
export type PublicErrorCode =
  | "invalid_input"
  | "too_fast"
  | "bot_check_failed"
  | "rate_limited"
  | "form_closed"
  | "link_invalid"
  | "link_expired"
  | "link_used"
  | "server_error";

export type PublicResult<T> = { ok: true; data: T } | { ok: false; code: PublicErrorCode };

export const ok = <T>(data: T): PublicResult<T> => ({ ok: true, data });
export const fail = <T = never>(code: PublicErrorCode): PublicResult<T> => ({ ok: false, code });

/**
 * Error codes for STAFF server functions. Staff functions throw `new Error(code)`;
 * the admin UI maps `error.message` to Thai/English text (adminContent[lang].errors).
 */
export type AdminErrorCode =
  | "unauthorized"
  | "forbidden"
  | "not_found"
  | "conflict"
  | "invalid_state"
  | "session_full"
  | "no_credit_left"
  | "already_booked"
  | "consent_required"
  | "responsibility_required"
  | "file_too_large"
  | "file_type"
  | "confirm_mismatch"
  | "family_restricted"
  | "server_error";

export function adminError(code: AdminErrorCode): Error {
  return new Error(code);
}

const ADMIN_CODES: readonly AdminErrorCode[] = [
  "unauthorized",
  "forbidden",
  "not_found",
  "conflict",
  "invalid_state",
  "session_full",
  "no_credit_left",
  "already_booked",
  "consent_required",
  "responsibility_required",
  "file_too_large",
  "file_type",
  "confirm_mismatch",
  "family_restricted",
  "server_error",
];

/**
 * Maps a supabase-js error (SQLSTATE in error.code, see 10-data-model.md § 16) to an AdminErrorCode.
 * Callers may handle a more specific case first (e.g. 23505 on bookings → "already_booked").
 * Never put error.message in logs or on screen: it can echo values.
 */
export function adminErrorFromDb(
  error: { code?: string; message?: string } | null | undefined,
): Error {
  const code = error?.code ?? "";
  const msg = error?.message ?? "";
  if (code === "23505") return adminError("conflict");
  if (code === "23503" || code === "P0002") return adminError("not_found");
  if (code === "23514") {
    if (/no sessions left/i.test(msg)) return adminError("no_credit_left");
    if (/parental/i.test(msg)) return adminError("responsibility_required");
    if (/processing is restricted/i.test(msg)) return adminError("family_restricted"); // D28
    return adminError("invalid_state");
  }
  if (code === "42501") return adminError("forbidden");
  return adminError("server_error");
}

/** Turns any thrown value into a known code. The generated auth middleware throws "Unauthorized: …". */
export function toAdminErrorCode(error: unknown): AdminErrorCode {
  const message = error instanceof Error ? error.message : "";
  if (message.startsWith("Unauthorized")) return "unauthorized";
  return (ADMIN_CODES as readonly string[]).includes(message)
    ? (message as AdminErrorCode)
    : "server_error";
}
```

**Public functions** (no login, or a private link) return `PublicResult<T>` and never throw for expected problems.
Their validator is a typed pass-through, and the zod check runs inside the handler with `safeParse`, so a bad payload
becomes `{ ok: false, code: "invalid_input" }` (see `submitBookingRequest`, § 9.1). Unexpected exceptions are caught
and become `server_error`.

**Staff functions** throw `adminError(code)`. Database errors arrive as SQLSTATE codes in `error.code`
(`10-data-model.md` § 16): handle the specific case you expect first (e.g. `23505` on a booking → `already_booked`,
`42501` from `upsert_child_health` → `consent_required`), then `throw adminErrorFromDb(error)` for the rest
(`23505` → `conflict`, `23503`/`P0002` → `not_found`, `23514` → `invalid_state` / `no_credit_left` /
`responsibility_required`, `42501` → `forbidden`). Zod failures from `.validator(schema)` throw a ZodError; the UI shows the
generic message for those (the form already validated with the same schema, so this only happens with tampering).

## 5. Logging without personal data

Anything a server function prints appears in Lovable → More → Cloud → Logs → Server logs (searchable for 5 days,
downloadable as JSON). Treat logs as **semi-public**.

- Allowed: `console.error("[<area>] <code>", { id })` where `<code>` is a short snake_case constant and `id` is a row
  UUID, a Postgres error code (`23505`) or an HTTP status.
- **Never** log: request bodies, `data`, names, phone numbers, LINE IDs, emails, messages, allergy/health fields, IP
  addresses or their hashes, tokens (link tokens, Turnstile tokens, LINE tokens), secrets, full URLs of private links,
  Supabase error `message`/`details` (they can echo values).
- Don't `console.log` on success. Don't log in the browser either (admin pages show errors on screen instead).
- `last_error` in `staff_notifications` follows the same rule (`missing_config`, `timeout`, `line_push_http_401`, …).

Good: `console.error("[booking] insert_failed", { code: error?.code ?? "unknown" })`
Bad: `console.error("insert failed", error, data)` (prints the parent's name and phone).

## 6. Auth middleware

Confirmed in `node_modules/@tanstack/start-client-core/dist/esm/createMiddleware.d.ts`: a function middleware supports
`createMiddleware({ type: "function" }).middleware([...]).server(...)`, and its `server` callback receives the earlier
middleware's context. So `requireStaff` can wrap the generated `requireSupabaseAuth` without editing it.

✅ `src/lib/backend/auth.middleware.ts` (F0-08):

```ts
import { createMiddleware } from "@tanstack/react-start";
import { requireSupabaseAuth } from "@/integrations/supabase/auth-middleware";
import { adminError } from "./result";

export type AppRole = "owner" | "staff";

/**
 * Signed-in user WITH a role. Adds `role` to the context on top of the generated
 * { supabase (RLS as this user), userId, claims }. Route guards are only UX; this is the check.
 */
export const requireStaff = createMiddleware({ type: "function" })
  .middleware([requireSupabaseAuth])
  .server(async ({ next, context }) => {
    const { data, error } = await context.supabase.rpc("current_app_role");
    if (error) throw adminError("server_error");
    const role = data as AppRole | null;
    if (role !== "owner" && role !== "staff") throw adminError("forbidden");
    return next({ context: { role } });
  });

/** Owner only (staff roles, privacy, consent texts, voiding payments). */
export const requireOwner = createMiddleware({ type: "function" })
  .middleware([requireStaff])
  .server(async ({ next, context }) => {
    if (context.role !== "owner") throw adminError("forbidden");
    return next();
  });
```

| Caller state | `getAdminMe` | any `requireStaff` fn | any `requireOwner` fn |
|---|---|---|---|
| Not signed in / expired | throws `Unauthorized: …` | throws `Unauthorized: …` | throws `Unauthorized: …` |
| Signed in, no role | `{ role: null }` | throws `forbidden` | throws `forbidden` |
| `staff` | `{ role: "staff" }` | ✓ | throws `forbidden` |
| `owner` | `{ role: "owner" }` | ✓ | ✓ |

Usage: `createServerFn({ method }).middleware([requireStaff]).validator(Schema).handler(async ({ data, context }) => …)`.
`context` then has `supabase`, `userId`, `claims` (from the generated middleware) and `role`.
Use `.validator`, never the deprecated `.inputValidator`.

**What must exist before this block type-checks (card P0-17, R-40).** The generated

**How a thrown code reaches the admin UI.** TanStack's server-function handler
(`@tanstack/start-server-core`, `server-functions-handler.js`) catches anything thrown by a function middleware or a
handler and returns it serialized (`x-tss-serialized` header, status 500); the browser-side call rethrows an `Error`
with the same `message`. So `adminError("forbidden")` arrives as `error.message === "forbidden"` and
`toAdminErrorCode` (§ 4) maps it. `errorMiddleware` in `src/start.ts` is a **request** middleware and never sees these
errors (it only handles errors thrown outside server functions). The framework logs `Server Fn Error!` with the error
in the server log: our messages are codes only, never data, so nothing personal reaches the log.

### 7.2 `hash.server.ts` ✅ (F0-02)

```ts
import "@tanstack/react-start/server-only";
import { requireServerEnv } from "./env.server";

const enc = new TextEncoder();
const toHex = (buf: ArrayBuffer): string =>
  [...new Uint8Array(buf)].map((b) => b.toString(16).padStart(2, "0")).join("");

export async function hmacSha256Hex(key: string, message: string): Promise<string> {
  const k = await crypto.subtle.importKey(
    "raw",
    enc.encode(key),
    { name: "HMAC", hash: "SHA-256" },
    false,
    ["sign"],
  );
  return toHex(await crypto.subtle.sign("HMAC", k, enc.encode(message)));
}

export async function sha256Hex(message: string): Promise<string> {
  return toHex(await crypto.subtle.digest("SHA-256", enc.encode(message)));
}

/** HMAC (not plain SHA-256: IPv4 space is small enough to brute-force). */
export async function hashIp(ip: string): Promise<string> {
  return hmacSha256Hex(requireServerEnv("IP_HASH_SECRET"), ip);
}
```

```ts
const SITEVERIFY = "https://challenges.cloudflare.com/turnstile/v0/siteverify";

/** Server-side Turnstile check. Fails CLOSED (false) on any problem; the UI then offers LINE. */
export async function verifyTurnstile(
  token: string,
  expectedAction: string,
  ip: string | null,
): Promise<boolean> {

    console.error("[turnstile] missing_config");
    return false;

    response: token,

      body,
      signal: AbortSignal.timeout(4000),

    return data.success === true && data.action === expectedAction;

    console.error("[turnstile] unreachable");
    return false;
  }
}
```

```ts
import "@tanstack/react-start/server-only";

/** Stateless channel access token: valid 15 min, unlimited issuance, can't be revoked. */
export async function issueLineStatelessToken(
  channelId: string,
  channelSecret: string,
  signal: AbortSignal,
): Promise<string> {
  const res = await fetch("https://api.line.me/oauth2/v3/token", {
    method: "POST",
    headers: { "Content-Type": "application/x-www-form-urlencoded" },
    body: new URLSearchParams({
      grant_type: "client_credentials",
      client_id: channelId,
      client_secret: channelSecret,
    }),
    signal,
  });
  if (!res.ok) throw new Error(`line_token_http_${res.status}`);
  const json = (await res.json()) as { access_token?: string };
  if (!json.access_token) throw new Error("line_token_missing");
  return json.access_token;
}

export type LinePushResult = { ok: boolean; status: number; error?: string };

/** Push one text message. `retryKey` must be a UUID; LINE answers 409 if it was already accepted. */
export async function pushLineText(opts: {
  channelId: string;
  channelSecret: string;
  to: string;
  text: string;
  retryKey: string;
  signal: AbortSignal;
}): Promise<LinePushResult> {
  try {
    const token = await issueLineStatelessToken(opts.channelId, opts.channelSecret, opts.signal);
    const res = await fetch("https://api.line.me/v2/bot/message/push", {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        Authorization: `Bearer ${token}`,
        "X-Line-Retry-Key": opts.retryKey,
      },
      body: JSON.stringify({
        to: opts.to,
        messages: [{ type: "text", text: opts.text.slice(0, 5000) }],
      }),
      signal: opts.signal,
    });
    if (res.ok || res.status === 409) return { ok: true, status: res.status };
    return { ok: false, status: res.status, error: `line_push_http_${res.status}` };
  } catch (e) {
    const name = e instanceof Error ? e.name : "";
    const msg = e instanceof Error ? e.message : "";
    if (name === "TimeoutError" || name === "AbortError")
      return { ok: false, status: 0, error: "timeout" };
    return { ok: false, status: 0, error: msg.startsWith("line_") ? msg : "network" };
  }
}
```

```ts
import "@tanstack/react-start/server-only";

/** x-line-signature = base64(HMAC-SHA256(channelSecret, rawBody)). Verify BEFORE JSON.parse. */
export async function verifyLineSignature(
  rawBody: string,
  signatureB64: string | null,
  channelSecret: string,
): Promise<boolean> {
  if (!signatureB64) return false;
  let sig: Uint8Array<ArrayBuffer>;
  try {
    sig = Uint8Array.from(atob(signatureB64), (c) => c.charCodeAt(0));
  } catch {
    return false;
  }
  const enc = new TextEncoder();
  const key = await crypto.subtle.importKey(
    "raw",
    enc.encode(channelSecret),
    { name: "HMAC", hash: "SHA-256" },
    false,
    ["verify"],
  );
  // crypto.subtle.verify compares in constant time
  return crypto.subtle.verify("HMAC", key, sig, enc.encode(rawBody));
}
```

### 7.7 `link-tokens.server.ts` ✅ (F4-03)

Private parent links (D13). The token appears **once**, in the URL staff copy into the family's LINE chat; only
`sha256(token)` is stored in `family_links.token_hash`.

```ts
import "@tanstack/react-start/server-only";
import { sha256Hex } from "./hash.server";
import { supabaseAdmin } from "./supabase-admin.server";

export type LinkPurpose = "enrol" | "manage";
export type ResolvedLink = {
  id: string;
  familyId: string;
  purpose: LinkPurpose;
  expiresAt: string;
};
export type LinkResolution =
  | { ok: true; link: ResolvedLink }
  | { ok: false; code: "link_invalid" | "link_expired" | "link_used" };

export const LINK_TOKEN_PATTERN = /^[A-Za-z0-9_-]{43}$/;

const toBase64Url = (bytes: Uint8Array): string =>
  btoa(String.fromCharCode(...bytes))
    .replace(/\+/g, "-")
    .replace(/\//g, "_")
    .replace(/=+$/, "");

/** 32 random bytes → 43-char base64url token. Only `tokenHash` is stored (D13). Show `token` once. */
export async function newLinkToken(): Promise<{ token: string; tokenHash: string }> {
  const token = toBase64Url(crypto.getRandomValues(new Uint8Array(32)));
  return { token, tokenHash: await sha256Hex(token) };
}

/** Never says WHY a hash didn't match; never logs the token. */
export async function resolveLinkToken(
  token: string,
  purpose: LinkPurpose,
): Promise<LinkResolution> {
  if (!LINK_TOKEN_PATTERN.test(token)) return { ok: false, code: "link_invalid" };
  const tokenHash = await sha256Hex(token);
  const { data, error } = await supabaseAdmin
    .from("family_links")
    .select("id, family_id, purpose, expires_at, used_at, revoked_at")
    .eq("token_hash", tokenHash)
    .eq("purpose", purpose)
    .maybeSingle();
  if (error) throw new Error("link_lookup_failed");
  if (!data || data.revoked_at) return { ok: false, code: "link_invalid" };
  if (new Date(data.expires_at).getTime() <= Date.now()) return { ok: false, code: "link_expired" };
  if (purpose === "enrol" && data.used_at) return { ok: false, code: "link_used" };
  return {
    ok: true,
    link: { id: data.id, familyId: data.family_id, purpose, expiresAt: data.expires_at },
  };
}
```

### 7.8 `staff-notify.server.ts` ✅ (rev) (F1-04; Stage A subset in card P1-03, consent kinds + delivery helpers in card P4-03)

(rev, R-41: `childrenCount: data.children_count ?? 0`, a type-only fix for the nullable generated column.)
The 4-second budget lives **here**, on the LINE token + push only (`AbortSignal.timeout(4000)`); the database calls
have no timeout. Callers such as `handleBookingRequest` simply `await notifyStaff(…)` and add no timeout of their own.

Outbox pattern: the `staff_notifications` row is written first, then LINE is called, then the row is updated. The
LINE retry key is the notification id, so a retry of the same row can never produce two messages (LINE answers 409).

```ts
import "@tanstack/react-start/server-only";
import { getRequestUrl } from "@tanstack/react-start/server";
import { formatSessionDate } from "@/lib/backend/dates";
import { buildStaffAlertText, type StaffAlertInput } from "@/lib/backend/staff-alert-text";
import { optionalServerEnv } from "./env.server";
import { pushLineText } from "./line-alert.server";
import { supabaseAdmin } from "./supabase-admin.server";

export type NotificationKind = "booking_request" | "enrolment_submitted" | "consent_withdrawn";
export type NotifyOutcome = {
  notificationId: string | null;
  status: "sent" | "failed" | "skipped";
};

/** PUBLIC_SITE_URL (no trailing slash) or the current request's origin. */
function siteBase(): string {
  return optionalServerEnv("PUBLIC_SITE_URL") ?? getRequestUrl().origin;
}

/** Builds the PII-free alert input from ids only. P1 version (no session join; F2-05 adds it). */
async function loadAlertInput(kind: NotificationKind, refId: string): Promise<StaffAlertInput> {
  const base = siteBase();
  if (kind === "booking_request") {
    const { data, error } = await supabaseAdmin
      .from("booking_requests")
      .select("ref_code, children_count, preferred_date")
      .eq("id", refId)
      .single();
    if (error || !data) throw new Error("ref_not_found");
    const date: string | null = data.preferred_date;
    return {
      kind,
      refCode: data.ref_code,
      dateLabel: date ? formatSessionDate(date, "th") : null,
      // generated column: the generated Row type is `number | null` (no NOT NULL); a request always has 1–3 children
      childrenCount: data.children_count ?? 0,
      adminUrl: `${base}/admin/inbox/${refId}`,
    };
  }
  if (kind === "enrolment_submitted") {
    return { kind, adminUrl: `${base}/admin/families/${refId}` };
  }
  const { data, error } = await supabaseAdmin
    .from("consent_records")
    .select("family_id, purpose")
    .eq("id", refId)
    .single();
  if (error || !data) throw new Error("ref_not_found");
  return { kind, purpose: data.purpose, adminUrl: `${base}/admin/families/${data.family_id}` };
}

async function finish(
  id: string,
  attempts: number,
  status: "sent" | "failed" | "skipped",
  lastError: string | null,
): Promise<void> {
  const { error } = await supabaseAdmin
    .from("staff_notifications")
    .update({
      status,
      attempts,
      last_error: lastError,
      sent_at: status === "sent" ? new Date().toISOString() : null,
    })
    .eq("id", id);
  if (error) console.error("[notify] outbox_update_failed", { id });
}

/**
 * Outbox + LINE push. NEVER throws: the caller's main write has already succeeded (D7).
 * Pass `opts.notificationId` to retry an existing row (same X-Line-Retry-Key → no duplicates).
 */
export async function notifyStaff(
  kind: NotificationKind,
  refId: string,
  opts: { notificationId?: string } = {},
): Promise<NotifyOutcome> {
  let id: string | null = opts.notificationId ?? null;
  let attempts = 0;
  try {
    if (id) {
      const { data } = await supabaseAdmin
        .from("staff_notifications")
        .select("status, attempts")
        .eq("id", id)
        .single();
      if (!data) return { notificationId: id, status: "failed" };
      if (data.status === "sent") return { notificationId: id, status: "sent" };
      attempts = data.attempts;
    } else {
      const { data, error } = await supabaseAdmin
        .from("staff_notifications")
        .insert({ kind, ref_id: refId, status: "pending" })
        .select("id")
        .single();
      if (error || !data) {
        console.error("[notify] outbox_insert_failed", { refId });
        return { notificationId: null, status: "failed" };
      }
      id = data.id as string;
    }

    const { data: settings } = await supabaseAdmin
      .from("studio_settings")
      .select("staff_alerts_enabled")
      .eq("id", true)
      .maybeSingle();
    if (settings?.staff_alerts_enabled === false) {
      await finish(id, attempts, "skipped", null);
      return { notificationId: id, status: "skipped" };
    }

    const channelId = optionalServerEnv("LINE_ALERT_CHANNEL_ID");
    const channelSecret = optionalServerEnv("LINE_ALERT_CHANNEL_SECRET");
    const to = optionalServerEnv("LINE_ALERT_TO");
    if (!channelId || !channelSecret || !to) {
      await finish(id, attempts + 1, "failed", "missing_config");
      return { notificationId: id, status: "failed" };
    }

    const text = buildStaffAlertText(await loadAlertInput(kind, refId));
    const result = await pushLineText({
      channelId,
      channelSecret,
      to,
      text,
      retryKey: id,
      signal: AbortSignal.timeout(4000), // one budget for token + push (D7)
    });
    await finish(
      id,
      attempts + 1,
      result.ok ? "sent" : "failed",
      result.ok ? null : (result.error ?? "unknown"),
    );
    return { notificationId: id, status: result.ok ? "sent" : "failed" };
  } catch {
    if (id) await finish(id, attempts + 1, "failed", "exception");
    console.error("[notify] exception", { refId });
    return { notificationId: id, status: "failed" };
  }
}
```

### 8.1 `ref-code.ts` ✅

```ts
/** Booking reference codes like CL-7KQ2M. No 0/O, 1/I/L to avoid misreading on LINE. */
export const REF_CODE_ALPHABET = "23456789ABCDEFGHJKMNPQRSTUVWXYZ";
export const REF_CODE_PATTERN = /^CL-[23456789ABCDEFGHJKMNPQRSTUVWXYZ]{5}$/;

/** `randomBytes` is injectable for tests; defaults to Web Crypto (works in browsers and Workers). */
export function makeRefCode(
  randomBytes: (n: number) => Uint8Array = (n) => crypto.getRandomValues(new Uint8Array(n)),
): string {
  const size = REF_CODE_ALPHABET.length; // 31
  const limit = 256 - (256 % size); // reject bytes >= 248 so every letter is equally likely
  let out = "";
  while (out.length < 5) {
    for (const byte of randomBytes(8)) {
      if (byte < limit && out.length < 5) out += REF_CODE_ALPHABET[byte % size];
    }
  }
  return `CL-${out}`;
}
```

```ts
/**
 * Thai phone numbers: mobile 0[6-9]XXXXXXXX (10 digits) or landline 0[2-7]XXXXXXX (9 digits).
 * Accepts spaces, dashes, dots, brackets and a +66 / 66 prefix. Returns digits only, starting with 0.
 */
export function normaliseThaiPhone(input: string): string | null {
  let digits = input.replace(/[\s\-.()]/g, "");
  if (digits.startsWith("+66")) digits = `0${digits.slice(3)}`;
  else if (digits.startsWith("66") && digits.length === 11) digits = `0${digits.slice(2)}`;
  if (!/^\d+$/.test(digits)) return null;
  if (/^0[6-9]\d{8}$/.test(digits)) return digits;
  if (/^0[2-7]\d{7}$/.test(digits)) return digits;
  return null;
}

export const isValidThaiPhone = (input: string): boolean => normaliseThaiPhone(input) !== null;
```

```ts
/** PDPA s.20(1): from age 10 the child's own consent is also needed (D11). */
export const CHILD_CONSENT_AGE = 10;

/**
 * Whole years between a birth month ("YYYY-MM" or "YYYY-MM-01") and a date ("YYYY-MM-DD").
 * The birthday is assumed to be the 1st of the month, so the result is never younger than the
 * real age (the safe side for consent). Must agree with SQL child_age_years().
 */
export function ageFromBirthMonth(birthMonth: string, on: string): number {
  const [by, bm] = birthMonth.split("-").map(Number);
  const [oy, om] = on.split("-").map(Number);
  if (!by || !bm || !oy || !om) throw new Error("invalid_date");
  return oy - by - (om < bm ? 1 : 0);
}

/** Unknown birth month → treat as needing the child's own consent (D11). */
export function needsChildConsent(birthMonth: string | null, on: string): boolean {
  if (!birthMonth) return true;
  return ageFromBirthMonth(birthMonth, on) >= CHILD_CONSENT_AGE;
}
```

## 9. Server-function catalogue

### 9.0 Conventions (apply to every function)

| Topic | Rule |
|---|---|
| Method | `GET` for reads, `POST` for writes. **Exceptions:** token functions (`getEnrolmentForm`, `getMyConsents`) are `POST` so the token travels in the body, not a query string; `getChildHealth` is `POST` because each call writes an audit row and must never run on prefetch/refetch. |
| CSRF | `src/start.ts` already applies `csrfMiddleware` to **all** server-function calls (GET and POST): same-origin only. Nothing to add. |
| Validator | Staff: `.validator(<Fn>Input)` (zod schema). Public/token: `.validator((input: <Raw type>) => input)` (a typed pass-through) + `safeParse` in the handler, so bad input becomes `{ ok: false, code: "invalid_input" }` instead of a throw. This is the one sanctioned exception to the README rule "use `.validator(schema)`" (R-42). |
| Schema names | `<FunctionName>Input` in PascalCase, e.g. `listBookingRequests` → `ListBookingRequestsInput`, in `<area>.schema.ts`. |
| Return | Public: `PublicResult<T>`. Staff: a camelCase view type from `<area>.schema.ts`, or `{ saved: true }` / `{ id }`. Never raw rows. |
| Errors | Staff: `throw adminError(code)`. Handle the specific SQLSTATE listed per function first, then `throw adminErrorFromDb(error)`. Public: any DB error → `server_error`, except `22023` (bad scope/arguments, e.g. from `submit_enrolment`) and `23514` (a business rule) → `invalid_input`. |
| Clients | Staff → `context.supabase`. Public/token → `supabaseAdmin`, every query filtered by the resolved id. Owner staff-role functions → `supabaseAdmin.auth.admin.*` after `requireOwner`. |
| Audit | Writes through `context.supabase` are audited by the `audit_row_change()` trigger with the staff user as actor. Health reads are audited inside the SQL functions. Don't write `audit_log` rows from TypeScript. |
| Paging | `PAGE_SIZE = 30` from `common.schema.ts`, `range(page * 30, page * 30 + 29)`, return `total` from `{ count: "exact" }`. |
| Dates | Send/receive `YYYY-MM-DD` for dates and ISO strings for timestamps. "Today" = `todayInBangkok()`. |

Phase gating: a function may only be added once the SQL file it needs has been applied (G4) and `types.ts` regenerated.
Each block below lists its phase and SQL dependency.

**Writing to Supabase under this repo's strict `tsconfig.json`** (`strict`, `exactOptionalPropertyTypes`,
`noUncheckedIndexedAccess`; R-43). Applies to every 📝 function:
- Build insert/update objects **without `undefined`-valued keys**: add an optional column with a conditional spread
  (`...(v.id ? { id: v.id } : {})`), never `{ id: v.id }` when `v.id` may be `undefined`. Zod output types carry
  `| undefined` on optional keys, so don't pass them to `.insert()`/`.update()` unchanged.
- An **update by id** chains `.select("id")` and throws `adminError("not_found")` when the returned array is empty
  (a plain `update()` returns no rows, so a missing id would otherwise look like success).
- Guard indexed access on returned arrays (`const row = data?.[0]; if (!row) throw adminError("not_found");`).
- Tests under `src/` are type-checked too: read mock calls with optional chaining (`mock.calls.at(0)?.[0]`) and avoid
  object literals with explicit `undefined` for optional properties.

✅ `uploadPaymentSlip` (FormData upload through the server function, so D3 holds and size/type are checked on the
server; works with the installed version, whose types accept `FormData` input for POST):

```ts
import { createServerFn } from "@tanstack/react-start";
import { requireStaff } from "./auth.middleware";
import { adminError } from "./result";

export const UPLOAD_MAX_BYTES = 5 * 1024 * 1024;
export const UPLOAD_TYPES: Record<string, string> = {
  "image/jpeg": "jpg",
  "image/png": "png",
  "image/webp": "webp",
  "application/pdf": "pdf",
};

/** Staff. FormData: paymentId, file. Stores at payment-slips/<family_id>/<uuid>.<ext> and links it. */
export const uploadPaymentSlip = createServerFn({ method: "POST" })
  .middleware([requireStaff])
  .validator((input: FormData) => {
    if (!(input instanceof FormData)) throw adminError("server_error");
    const paymentId = input.get("paymentId");
    const file = input.get("file");
    if (typeof paymentId !== "string" || !/^[0-9a-f-]{36}$/i.test(paymentId))
      throw adminError("not_found");
    if (!(file instanceof File)) throw adminError("file_type");
    if (file.size > UPLOAD_MAX_BYTES) throw adminError("file_too_large");
    if (!UPLOAD_TYPES[file.type]) throw adminError("file_type");
    return { paymentId, file };
  })
  .handler(async ({ data, context }) => {
    const { data: payment, error } = await context.supabase
      .from("payments")
      .select("id, family_id")
      .eq("id", data.paymentId)
      .maybeSingle();
    if (error) throw adminError("server_error");
    if (!payment) throw adminError("not_found");
    const path = `${payment.family_id}/${crypto.randomUUID()}.${UPLOAD_TYPES[data.file.type]}`;
    const { error: upErr } = await context.supabase.storage
      .from("payment-slips")
      .upload(path, data.file, { contentType: data.file.type, upsert: false });
    if (upErr) throw adminError("server_error");
    const { error: linkErr } = await context.supabase
      .from("payments")
      .update({ slip_path: path })
      .eq("id", data.paymentId);
    if (linkErr) throw adminError("server_error");
    return { slipPath: path };
  });
```

```ts
/** zod → token → texts shown are current → ONE SQL transaction → alerts. Never throws. */
export async function handleSubmitEnrolment(
  data: SubmitEnrolmentRaw,
): Promise<PublicResult<{ submitted: true }>> {
  const parsed = SubmitEnrolmentInput.safeParse(data);
  if (!parsed.success) return fail("invalid_input");
  const v = parsed.data;
  try {
    const res = await resolveLinkToken(v.token, "enrol");
    if (!res.ok) return fail(res.code);

    // The texts the parent saw must be current texts for the right purpose and language.
    const shown: Array<{ id: string; purpose: ConsentPurpose }> = [];
    for (const c of v.children) {
      if (c.health.decision !== "skipped")
        shown.push({ id: c.health.consentTextId, purpose: "health_allergy" });
      for (const m of c.media) shown.push({ id: m.consentTextId, purpose: m.purpose });
    }
    if (!(await areCurrentConsentTexts(shown, v.lang))) return fail("invalid_input");

    const { data: out, error } = await supabaseAdmin.rpc("submit_enrolment", {
      p_link_id: res.link.id,
      p: toSubmitEnrolmentPayload(v),
    });
    if (error) {
      console.error("[enrol] rpc_failed", { code: error.code ?? "unknown" });
      return fail(error.code === "22023" || error.code === "23514" ? "invalid_input" : "server_error");
    }
    const result = SubmitEnrolmentRpcResult.safeParse(out);
    if (!result.success) return fail("server_error");
    if (!result.data.ok) return fail(result.data.code);

    // Alerts the consent trigger queued (withdrawals, D29), then the "enrolment submitted" alert.
    await deliverAlertIds(result.data.alert_ids);
    await notifyStaff("enrolment_submitted", result.data.family_id);
    return ok({ submitted: true as const });
  } catch {
    console.error("[enrol] submit_failed");
    return fail("server_error");
  }
}
```

Key behaviours:
- Every service-role query filters by `familyId` from the resolved link (D4); `submit_enrolment` re-checks that every

- The consent text ids the parent saw are checked: current, right purpose, right language. A version published while
  the form was open → `invalid_input` (UI: "please reload").
- Health: `granted` → consent record first, then `upsert_child_health` (inside SQL). `refused` ("I don't want to share

`getPrintSheet` (staff, **POST**, `requireStaff`, `.validator(PrintSheetInput)`):

1. **Audit first, fail closed.** `context.supabase.rpc("record_family_print", { p_family_id, p_include_health })` (cross-file SQL,
   a definer function that calls `log_audit_event`). It writes one `audit_log` row: action `print_record` (the only print audit name, round two), table `families`, row id

2. Family (`display_name, processing_restricted_at`). Missing → `not_found`.
3. Guardians (`id, full_name, phone, is_primary, has_parental_responsibility, responsibility_attested_at`) and their current

4. Children (`id, nickname, birth_month, reported_age_years, is_active`), **one** `rpc("consent_matrix", { p_child_ids })`, and the

   version and `sha256` prefix.
```ts
import { createFileRoute } from "@tanstack/react-router";
import { optionalServerEnv } from "@/server/env.server";
import { verifyLineSignature } from "@/server/line-signature.server";
import { issueLineStatelessToken } from "@/server/line-alert.server";

type LineEvent = {
  type: string;
  replyToken?: string;
  source?: { type?: string; groupId?: string };
};

/**
 * OPTIONAL (F1-08). Webhook of the "CherryLee Staff Alerts" OA ONLY — never @cherryleeandco (D6).
 * Its only job: when the bot joins a staff group, reply the group id INTO that group (replies are
 * free) so the owner can copy it into LINE_ALERT_TO. Stores nothing, logs nothing personal.
 */
export const Route = createFileRoute("/api/line/alert-webhook")({
  server: {
    handlers: {
      POST: async ({ request }) => {
        const secret = optionalServerEnv("LINE_ALERT_CHANNEL_SECRET");
        const channelId = optionalServerEnv("LINE_ALERT_CHANNEL_ID");
        if (!secret || !channelId) return new Response("not configured", { status: 503 });

        const raw = await request.text(); // raw body FIRST, verify, then parse
        if (!(await verifyLineSignature(raw, request.headers.get("x-line-signature"), secret))) {
          return new Response("unauthorized", { status: 401 });
        }
        let events: LineEvent[] = [];
        try {
          events = (JSON.parse(raw) as { events?: LineEvent[] }).events ?? [];
        } catch {
          return new Response("bad request", { status: 400 });
        }
        for (const e of events) {
          if (e.type !== "join" || !e.replyToken || !e.source?.groupId) continue; // ignore all messages
          try {
            const signal = AbortSignal.timeout(4000);
            const token = await issueLineStatelessToken(channelId, secret, signal);
            await fetch("https://api.line.me/v2/bot/message/reply", {
              method: "POST",
              headers: { "Content-Type": "application/json", Authorization: `Bearer ${token}` },
              body: JSON.stringify({
                replyToken: e.replyToken,
                messages: [
                  {
                    type: "text",
                    text: `เชื่อมต่อกลุ่มแจ้งเตือนแล้วค่ะ\nGroup ID: ${e.source.groupId}`,
                  },
                ],
              }),
              signal,
            });
          } catch {
            console.error("[alert-webhook] reply_failed");
          }
        }
        return new Response("ok"); // LINE only needs a fast 200
      },
    },
  },
});
```

## 14. View types and handler skeletons (R-13)

Every 📝 function in § 9 returns one of the types below. Declare each type **exactly as written** in the named
`<area>.schema.ts` (browser-safe, no imports from `@/server/*`). Map snake_case SQL columns to camelCase with the table
under each type; never return a raw row. All skeletons use the patterns already compiled in §§ 9.1–9.3: `requireStaff`
(or `requireOwner`), `context.supabase` (RLS as the staff user), `adminError` / `adminErrorFromDb`, and
`(data ?? []) as Array<{…}>` casts **only** for rows whose shape is spelled out in the cast. Date strings stay
`YYYY-MM-DD`, timestamps stay ISO strings. Columns that arrive with a later migration are filled with `null` / `[]`
by the earlier card and filled in by the card named in the comment.
